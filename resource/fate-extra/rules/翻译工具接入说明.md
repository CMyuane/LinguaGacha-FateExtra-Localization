# Fate/EXTRA 文本安全分类接入说明

## 交付文件

- `FE文本安全分类.jsonl`：全部日文原文条目的逐条安全分类。
- `FE文本安全分类.sqlite`：供 GUI 按 `path + char` 即时查询的索引数据库。
- `FE文本安全分类汇总.json`：分类数量、源文件哈希和覆盖校验。
- `classification_validation.json`：唯一键、策略字段、共享组及代表性条目的验证结果。
- `classification_progress.json`：最近一次分类任务状态。
- `G:\FE\reverse\classify_all_text_storage.py`：可重复运行的分类器源码。
- `G:\FE\reverse\build_text_classification_sqlite.py`：SQLite 索引生成器源码。

## 路径与可移植性

分类数据的唯一查询键 `path + char` 以及 `resource_path` 都是相对资源键，不包含盘符或本机工程目录。

两个生成脚本均不绑定 `G:` 或任何绝对路径：

- 命令行参数优先；
- 未传参数时读取环境变量 `FE_PROJECT_ROOT`；
- 环境变量也不存在时，使用脚本目录的上一级作为工程根目录。

分类器支持：

```text
--project-root
--resource-root
--source-text
--output-dir
--u16-analysis
--expected-entries
```

示例：

```powershell
python classify_all_text_storage.py `
  --resource-root "D:\MyFE\output" `
  --source-text "D:\MyFE\output\Fate_Extra_JP_完整文本汇总.txt" `
  --output-dir "D:\MyFE\classification" `
  --u16-analysis "D:\MyFE\build\u16_reference_segment_analysis.json"
```

SQLite 生成器支持：

```text
--project-root
--input-jsonl
--output-db
```

示例：

```powershell
python build_text_classification_sqlite.py `
  --input-jsonl "D:\MyFE\classification\FE文本安全分类.jsonl" `
  --output-db "D:\MyFE\classification\FE文本安全分类.sqlite"
```

## 唯一键

翻译工具必须使用以下组合查找分类：

```text
path + char
```

不得仅以原文内容查找。相同日文可能在多个 DAT、多个地址中采用不同的存储方式。

示例：

```json
{
  "path": "FE_完整提取\\pak_unpacked\\7b37eddc1ba71bc1\\field\\016\\0000.dat",
  "char": 66540
}
```

## 核心字段

| 字段 | 含义 |
|---|---|
| `path` | 完整提取文本中的定位路径 |
| `char` | 完整提取文本中的字符偏移 |
| `source` | 日文原文 |
| `category` | 程序使用的英文分类代码 |
| `category_zh` | 面向译者显示的中文分类 |
| `confidence` | 分类证据等级 |
| `reason` | 归类依据 |
| `byte_offset` | 文本在资源中的原始字节位置 |
| `source_bytes` | 原文编码字节数 |
| `slot_capacity` | 原槽位可用字节数 |
| `allow_overlength` | 是否允许译文超过原槽位 |
| `allow_relocation` | 是否允许重定位 |
| `translator_message` | 应直接显示给人工译者的提示 |

部分类型还会提供：

- `pointer_offsets`
- `address_limit`
- `preserve_high16`
- `shared_group_id`
- `shared_group_start`
- `shared_group_end`
- `shared_group_members`
- `format_handler`

## 分类代码与工具行为

### `ordinary_independent_slot`

显示：

> 普通独立槽位：译文不得超过原槽位容量，只能原位替换。

工具要求：

- 实时计算译文的游戏编码字节数；
- 超过 `slot_capacity` 时标红并禁止进入自动注入；
- 不允许重定位。

这里确认的是独立 NUL 边界，不代表已经解析出运行时调用指针，因此只授予原位写入权限。

### `confirmed_u32_pointer`

显示：

> 已确认32位指针：允许超出原槽位；注入器必须重定位文本并更新完整32位指针。

工具要求：

- 允许译文超过 `slot_capacity`；
- 注入阶段必须使用 `pointer_offsets` 更新所有已确认指针；
- 不能只覆盖原槽位或截断译文。

### `packed_u16_pointer`

显示：

> 低16位分段地址：允许适当超长；只能重定位到 DAT 前64 KiB内，并且只更新地址低16位。

工具要求：

- 可以允许超长；
- 新地址必须小于 `address_limit`，当前为 `65536`；
- 只更新记录低16位；
- 必须保留高16位；
- 找不到范围内安全空间时要求译者缩短。

当前只把已有结构证据确认的记录标成此类。尚未确认的疑似低16位条目不会获得超长权限。

### `shared_overlapping_view`

显示：

> 共享/重叠视图：禁止单条独立补零、扩写或重定位，必须按共享组整体处理。

工具要求：

- 使用 `shared_group_id` 聚合同组条目；
- 禁止把单条译文补零到 `slot_end`；
- 不支持整组处理时，禁止该组进入自动注入；
- 不同资源中的共享组编号不得混用。

### `dynamic_cursor_no_static_ref`

显示：

> 动态游标/无静态引用：译文不得超过原槽位容量，只能在原位置替换。

工具要求：

- 超过 `slot_capacity` 时禁止保存为可注入状态；
- 禁止重定位；
- 允许保留超长译文草稿，但必须显示“需要缩短”。

### `fixed_layout_text`

显示：

> 固定布局文本：默认禁止超长；只有对应专用格式处理器允许时才能例外。

工具要求：

- 默认按 `slot_capacity` 限制；
- 如果存在 `format_handler`，必须调用对应专用处理器；
- 不得使用通用 DAT 文本重定位器处理。

### `unresolved_candidate`

显示：

> 未解析候选：可以校对译文，但在完成结构分类前禁止自动注入。

工具要求：

- 允许录入和保存译文；
- 明确显示“待解析”；
- 禁止进入自动注入队列；
- 后续重新分类后才能解除限制。

## 字节数计算

不得使用 Python、JavaScript 或界面控件的普通字符串长度代替游戏编码长度。

工具必须使用最终字库映射计算：

```text
translated_encoded_bytes
```

然后与 `slot_capacity` 比较。控制符也必须按照游戏实际编码计入长度。

## 分类优先级

同一条目只输出一个主分类，优先级如下：

1. 共享/重叠视图
2. 固定布局文本
3. 低16位分段地址
4. 已确认32位指针
5. 动态游标/无静态引用
6. 普通独立槽位
7. 未解析候选

共享段优先级最高，因为即使其中某个起点同时存在指针，也不能忽略同一 NUL 区间内的其他提取视图。

## 重要边界

“完成全量分类”表示每一条原文都有明确的工具处理策略，不表示所有游戏格式都已经逆向完成。

尤其是 `unresolved_candidate`：它本身就是一种有效且安全的分类结果。工具必须拒绝自动注入，而不能为了追求更高的可注入比例把它猜成普通槽位。
