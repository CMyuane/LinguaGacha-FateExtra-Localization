# Fate/EXTRA 本地化版：Codex 功能与维护指引

本文面向后续使用 Codex 或其他代码代理维护本项目的开发者。修改前应先阅读本文件、根目录 `AGENTS.md`、`README.md`，并检查相关测试。

## 1. 项目定位

本分支是 LinguaGacha 的 Fate/EXTRA 专用文本校对工具，只处理文本工程、PSP 显示预览、术语和注入安全信息，不负责直接构筑游戏 ISO。

禁止把游戏 ISO、CPK、DAT 解包资源、翻译工程数据库（`.lg`/`.sqlite`）或用户 API 密钥提交到仓库或发布包。

## 2. 三层文本工作流

Fate/EXTRA 工作台同时维护三个相互独立的文本层：

1. **日文原文**：只读，作为结构、控制符和上下文基准。
2. **Lingua 初翻**：机器翻译草稿，可由翻译任务更新。
3. **最终校对稿**：人工润色和最终交付文本，不应被后续机翻自动覆盖。

精简工程中，尚无中文初翻的条目以日文原文填入初翻栏，但保留原翻译状态，不能因此自动标记为“已翻译”。

## 3. PSP 预览与显示规则

- 对话文本默认每行最多 20 个实际显示字符，最多 3 行。
- 全屏文本使用独立的每行 30 字上限。
- 控制符不计入显示字符数；可见标点计入。
- 显示类型可自动判定，也可人工指定对话、全屏或诗文模式。
- Ruby 结构必须保持 `#RUBS...#RUBE...#REND` 的顺序和完整性。
- Ruby 注音使用独立基线，修改绘制逻辑时必须验证其不会与上一行正文重叠。

核心文件：

- `src/shared/fate-extra/fate-extra-layout.ts`
- `src/frontend/pages/fate-extra-preview-page/page.tsx`
- `src/frontend/pages/fate-extra-preview-page/fate-extra-preview-page.css`

## 4. 上下文查看

PSP 预览中的“查看上下文”固定显示：

- 前两条
- 当前条
- 后两条

顺序来自完整日文主库中同一 DAT 资源块的 `char` 顺序，并同时显示日文原文、Lingua 初翻和最终校对稿。

上下文采用按需数据库查询，禁止重新引入覆盖约 91 万条记录的持久上下文索引。旧方案会令约 583 MiB 的工程增长到约 904 MiB；当前方案在真实 28,433 条精简工程中的样例查询约为 335 ms，验证工程仅产生正常数据库迁移增长。

核心文件：

- `src/backend/database/database-operations.ts`
- `src/backend/toolbox/fate-extra-service.ts`
- `src/backend/api/routes/toolbox-routes.ts`

## 5. 精简工程与重复文本

- `fate_extra_compact_source` 保存去重后的可编辑原文。
- `fate_extra_compact_occurrence` 保存原文在完整主库中的所有出现位置。
- 选择六条剧情路线之一时，预览必须按该路线的物理 `row_number` 顺序投影，不能按共享条目 ID 或代表条目排序。
- 相同日文原文在不同路线中可以具有不同初翻；初翻按路线、资源路径和 `char` 索引保存，最终校对稿仍可由共享去重组统一维护。
- `FE_补漏.txt` 在唯一文本模式下必须按原文精确去重，顶部分类计数与底部分页总数都显示有效唯一文本数；仅物理位置模式允许展开全部重复位置。
- 编辑一条去重文本时，导出阶段仍必须能回填至全部对应索引。
- 上下文查询应通过 occurrence/source 恢复 DAT 内顺序，不得把 91 万条出现位置复制进新的永久表。
- 对精简工程执行数据库迁移时，空初翻填入原文，但不改变翻译状态。

当前 PSP 预览的全屏文本使用 16px 字体、15px 字符推进；这使字距比例接近角色对白，同时仍能在 480px 画布中容纳每行 30 字。不要恢复旧的 17px 字体配 14px 推进，否则汉字会明显挤压。

## 6. 注入安全信息

工具只负责显示和校验安全分类，不应擅自把“未解析候选”改为可注入。已知类别包括：

- 普通独立槽位
- 已确认 32 位指针
- 低 16 位分段地址
- 共享或重叠视图
- 动态游标或无静态引用
- 固定布局文本
- 未解析候选

任何放宽规则都必须基于 DAT 结构证据和实际注入验证，并同步更新安全分类数据库、用户提示和测试。

## 7. 必须保持的 UI 行为

- 原文、初翻、校对稿三个编辑区必须始终可见且互不覆盖。
- 注入安全信息不得覆盖操作按钮或文本框。
- 切换显示类型后，翻页、跳转和滚轮仍必须可用。
- PSP 预览工作区应能滚动查看全部内容。
- 大型工程不得在渲染线程一次性载入全部 91 万条原始记录。

## 8. 修改后的最低验证

提交前至少执行：

```text
tsc --noEmit
oxlint .
node buildtools/check/index.mjs
```

并运行 Fate/EXTRA 定向测试，覆盖：

- 三层文本保存
- 空初翻迁移
- 前后各两条上下文
- Ruby 行距
- 对话/全屏行宽
- 精简工程重复文本映射
- 六路线物理顺序与分路线初翻
- 补漏唯一文本计数

真实工程回归基准：条目数 28,433、空初翻 0、上下文返回目标及前后共 5 条。

## 9. 发布约定

- 源码通过独立分支和 Draft PR 提交，不直接覆盖 `main`。
- Windows 免安装版以完整 `win-unpacked` 目录压缩为 ZIP。
- 每次发布创建新的 GitHub Release 和版本标签，不覆盖旧版本。
- 发布包根目录必须包含本文件，便于 Codex 在脱离源码仓库时理解新增功能和维护约束。
